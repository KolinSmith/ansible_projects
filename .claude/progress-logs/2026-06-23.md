### Forgejo CI Runner (192.168.9.101) — Docker Crashed, Recovered

**Discovery**: Docker daemon had been crashed since June 19.

**Root cause**: Containerd image layer cache (`/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs`) grew to 8.5GB with no cleanup, filling the 29GB eMMC. When the disk was full, containerd couldn't write state files and corrupted itself. 35 of its plugins entered error state on next restart.

**Fix**:
1. Wiped `/var/lib/containerd` (11GB total freed)
2. Wiped stale Docker container metadata from `/var/lib/docker/containers/`
3. Restarted containerd + Docker
4. Restarted `forgejo-runner` and `beszel-agent` containers via compose

**Prevention added** (PR #22):
- Weekly `docker system prune -af` cron (Sunday 3 AM) on forgejo-runner host — prevents cache accumulation
- Hourly disk space heartbeat to Uptime Kuma push monitor `oCTYwPZKEB` — alerts if disk >80%; cron installed to root's crontab on 192.168.9.101

### Forgejo CI Runner — Registry Auth Fix

**Problem**: Runner couldn't pull `ci-tools:latest` from Forgejo container registry (`100.86.4.29:3001`).

**Root cause**: `docker login` had previously been run as root (`sudo docker login`), storing credentials in `/root/.docker/config.json`. The runner container runs as uid 1000 / gid 999 (docker group) — couldn't read root's config.

**Fix**:
- Ran `docker login` as `dax` user (not sudo) → credentials in `/home/dax/.docker/config.json`
- Set `chgrp docker && chmod 640` so the runner's gid (999) can read it
- Mounted `/home/dax/.docker/config.json:/data/.docker/config.json:ro` into runner container
- Deleted root's `/root/.docker/config.json`
- PR #21 on docker_projects: `fix/forgejo-runner-registry-auth`
- Also fixed `deploy_docker_env` Ansible role to: (a) remove `sudo` from docker login, (b) add permissions fix task for forgejo-runner (PR #22)
